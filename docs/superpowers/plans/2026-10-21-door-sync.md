# Door Synchronization Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans task by task. Keep tests
> and an execution ledger; obtain a fresh whole-branch review before publishing.

**Goal:** Share nearby ordinary door openings with opt-out and manual opening.

**Architecture:** A portable door authority runs inside either session host.
Clients retain authoritative value state; the native adapter applies it only in
an engine callback for the live matching door actor.

**Tech Stack:** Existing C++17, UDP, Win32 and ImGui. No new runtime dependency.

**Spec:** `docs/superpowers/specs/2026-10-21-door-sync-design.md`.

## Global Constraints

- Preserve the exact pose wire format from PR #98 and existing movement sequencing.
- Initial support is ordinary doors opening, not arbitrary scripted state changes.
- Keep native reverse-engineering output and probes outside the repository.
- 200 m enter / 250 m exit; manual range 3 m; synchronization defaults on.
- Door hotkey defaults unbound; normal opening remains available with sync off.
- Engine calls never run on socket/render threads; queued commands contain values.
- Publish truthful validation limits. Two local probes do not validate multiplayer.

## Review Focus

- A report before the first interest packet must recover through retries.
- A door loaded after its state was acknowledged still receives that state.
- Turning synchronization off during a queued opening must prevent application.
- A reused actor address must not transfer a previous door's identity.
- A legacy host must not leave the UI falsely claiming door synchronization works.

## Task 1: Portable state and packet contract

Files: create `src/net/doors.h`, `src/net/doors.cpp`, `tests/door_test.cpp`.

Interfaces: `net::doors::Key` contains world and quantized placement;
`Message` contains opcode, delivery ID and revision. `Authority::receive`,
`Authority::tick`, `Authority::remove` and `Authority::reset` own session state.
`Client::interest`, `Client::opened`, `Client::receive`, `Client::tick` and
`Client::isOpen` provide bounded value-only client state.

- [ ] Implement canonical identity, a versioned fixed-size payload and bounded retries.
- [ ] Test loss of report/ack/state, duplicate/simultaneous reports, 200/250 m
